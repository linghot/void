# 模型选型与性能预算

> 下表体积/内存/延迟均为**估算区间**，用于排布方案与做取舍；
> 具体数值必须在你真机上实测（同一模型在不同 SoC 上差 2–3 倍很正常）。

## 1. 语音识别（ASR）

| 方案 | 模型体积 | 内存占用 | 是否流式 | 中文效果 | 备注 |
|---|---|---|---|---|---|
| **sherpa-onnx** 流式 zipformer/paraformer | 50–300 MB | 150–500 MB | ✅ 流式 | 好 | **首选**：k2/icefall 系，安卓官方有 demo，可增量出字 |
| **whisper.cpp** tiny | ~40 MB | ~200 MB | ❌ 需分段 | 一般 | 最省资源，配 VAD 用，适合先跑通 |
| whisper.cpp base | ~80 MB | ~350 MB | ❌ 需分段 | 较好 | 延迟与质量折中 |
| whisper.cpp small | ~250 MB | ~800 MB | ❌ 需分段 | 好 | 手机上偏重，发热明显 |
| **Vosk** 中文小模型 | 40–50 MB | ~150 MB | ✅ 流式 | 一般 | 轻量，但中文识别准确率明显低于上面两个 |

**建议路径**：先用 whisper.cpp tiny + VAD 把管线跑通（M2 阶段性目标），
再换 sherpa-onnx 流式模型上质量。

## 2. 断句 / 端点检测（VAD）

| 方案 | 体积 | 说明 |
|---|---|---|
| 能量阈值（本项目已实现） | 0 | 零依赖，先跑通用；对背景噪声敏感 |
| **Silero VAD**（ONNX） | ~2 MB | 效果远好于能量法，接 ONNX Runtime Mobile 即可 |

## 3. 翻译（MT）

| 方案 | 模型体积 | 内存 | 延迟/句 | 质量 | 备注 |
|---|---|---|---|---|---|
| 自建 HTTP API（你现有的 API） | 0（本地） | 0 | 取决于网络 | 最好 | **不是离线**，但最省手机资源，可随时切换模型 |
| **OPUS-MT**（Marian，单语向） | ~75 MB/语向 | ~200 MB | 50–200 ms | 中上 | CTranslate2 int8，中英一个模型一对 |
| **NLLB-200 distilled 600M** | ~600 MB（int8） | ~900 MB | 200–600 ms | 好 | 一个模型覆盖多语种，体积换通用性 |
| llama.cpp + Qwen2.5-0.5B/1.5B-Instruct Q4 | 400 MB / 1 GB | 700 MB–2 GB | 0.5–3 s | 好（且能做润色） | 手机上偏慢，适合中高端机 |
| Android 系统自带翻译 | 0 | 0 | 快 | 一般 | 机型/区域差异大，不作为主方案 |

**混合策略（推荐）**：默认走**你的 HTTP API**（质量最好、手机最省电）；
只有在你要求"完全离线"时才切到本地 OPUS-MT/NLLB，并接受质量与延迟损失。

## 4. 朗读（TTS，可选）

用 **Android 系统 TTS 引擎**即可，多数机型支持离线中文语音包，
无需内置模型。注意首次使用需下载语音数据（部分 ROM 需要手动安装）。

## 5. 延迟预算（端到端，目标 1–3 秒）

```
音频采集          20–50 ms
VAD 判定句子结束  300–800 ms   ← 这部分是"等一句话说完"的固有延迟，可调
ASR 出字          200–800 ms   ← 流式模型可边出边翻，能明显改善体感
翻译              100–600 ms   ← 本地模型 vs 你的 API 差别很大
字幕渲染          < 50 ms
------------------------------------
合计              约 0.7–2.3 s（理想） / 2–4 s（保守）
```

**要压到 1 秒内**：必须用流式 ASR + 边出边翻 + 缩短 VAD 静音判定（代价是断句更碎）。

## 6. 内存与发热红线

- 中低端机建议总内存占用控制在 **1 GB 以内**，否则后台容易被系统杀
- 连续跑 30 分钟以上要实测发热与降频；降频会直接拉高延迟
- 模型放 `models/` 后拷到 App 私有目录或外部存储，按需 mmap 加载

## 7. 接入顺序建议

1. `Translator` 先接你的 HTTP API（`Translator.kt` 里已写好 OpenAI 兼容实现）→ 立刻可用
2. `AsrEngine` 先接 whisper.cpp tiny → 验证识别链路
3. 再换 sherpa-onnx 流式 → 提质量与降延迟
4. 最后按需加本地 MT 与 TTS

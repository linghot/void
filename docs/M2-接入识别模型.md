# M2：接入离线识别（whisper.cpp）

> 本文对应工程版本 **v0.2-m2**。
> M0 的结论是 **CAPTURABLE**（手机内播放的音频抓得到），所以按计划接真识别。

---

## 1. 这一步做了什么

| 文件 | 作用 |
|---|---|
| `app/src/main/cpp/CMakeLists.txt` | 构建时用 FetchContent 拉取 whisper.cpp 并静态链接 |
| `app/src/main/cpp/whisper_jni.cpp` | JNI 外壳：Kotlin ↔ whisper C API |
| `pipeline/WhisperAsrEngine.kt` | 识别引擎：PCM16 → float → whisper_full → 文本 |
| `pipeline/ModelStore.kt` | 模型放哪、下没下、怎么下（tiny / base / small） |
| `service/InterpreterService.kt` | `chooseAsr()`：模型就绪用 whisper，否则自动退回占位实现 |
| `MainActivity` + 布局 | 新增第 3 步「下载识别模型」，并显示识别耗时 |

**设计要点：识别引擎是可降级的。** 原生库没编进来、模型没下载、模型文件损坏，
`prepare()` 都返回 false，管线自动退回占位识别——**不会闪退**，你会看到
`[ASR未接入 …ms]` 而不是崩溃。

## 2. 你要做的三件事

### ① 重新构建（云构建即可）

工程新增了 **NDK + CMake** 编译，工作流里我已经加了自动安装 NDK 的步骤。
把新代码推上去，`Actions → Build debug APK` 跑一次，产物还是
`app/build/outputs/apk/debug/app-debug.apk`。

首次构建会多花几分钟（要拉取并编译 whisper.cpp）。
如果本地用 Android Studio，需要装：**NDK 26.1.10909125** + **CMake 3.22.1**
（SDK Manager → SDK Tools 里勾选）。

### ② 装好后点第 3 步下载模型

模型不放 APK 里（否则安装包 200 MB+），运行时下到：

```
/sdcard/Android/data/com.dsh.offlineinterp/files/models/asr/
```

三个选项：

| 模型 | 体积 | 特点 | 建议 |
|---|---|---|---|
| `ggml-tiny.bin` | 约 75 MB | 最快，中文一般 | 只做链路验证时用 |
| `ggml-base.bin` | 约 142 MB | 平衡 | **默认，先用这个** |
| `ggml-small.bin` | 约 466 MB | 中文明显更好，推理慢 | 手机性能好、能等的话选它 |

下载地址（whisper.cpp 官方模型库）：
`https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-<型号>.bin`

也可以不用 App 下载：自己把文件拷到上面那个目录，App 一启动就会发现。

### ③ 启动同传，看悬浮字幕

第 5 步 → 录屏授权 → 悬浮字幕出现。现在字幕分三行：

```
<识别出的原文>
<译文>            ← 现在是 NoopTranslator，即原文（还没接翻译）
(3020ms 音频 · 识别 1650ms · whisper.cpp(ggml-base.bin) · noop)
```

第三行是给调优用的：**音频时长 vs 识别耗时**，直接反映延迟有没有失控。

## 3. 关于你上次的削波问题（重要）

你提交的探针数据里 **峰值 32765 持续 6 秒以上**，这就是**削波**（信号顶到满量程），
不是音量大那么简单——削掉的波形信息是找不回来的，识别准确率会明显下降。

我在探针里加了**削波占比**统计和告警，下次跑探针会直接告诉你削了百分之几。现在能做的：

1. **把手机音量降到 60~70%** 再跑一次探针，让峰值落在 20000~28000 之间最理想
2. 如果降音量还削波（说明是 App 内部增益问题），告诉我，我加一个软限幅 + 自动增益（AGC）在采集端

## 4. 预期效果与延迟

| 环节 | 预期 |
|---|---|
| 识别准确率 | base 模型对清晰中文对白可用；背景音乐大、语速快时明显下降 |
| 端到端延迟 | 静音等待 0.5 s + 推理 0.5~2 s ≈ **1.5~3 秒**（base，4 线程，5 秒句子） |
| CPU/发热 | base 持续推理会让中端机明显发热，长时间用会降频 |

**这就是为什么下一步是 sherpa-onnx 流式**：whisper 不是流式模型，
必须等一句话说完才能开始识别，延迟天然下不去。

## 5. 下一步：M3 换成 sherpa-onnx 流式（已核实的接入路径）

官方**没有 Maven 包**，只有 GitHub Releases 里的预编译 `.so`（我核实过官方文档）：

1. 下载 `sherpa-onnx-v1.13.8-android.tar.bz2`
   （地址：`https://github.com/k2-fsa/sherpa-onnx/releases/download/v1.13.8/sherpa-onnx-v1.13.8-android.tar.bz2`）
2. 解压出 `libonnxruntime.so` + `libsherpa-onnx-jni.so`，
   放进 `app/src/main/jniLibs/arm64-v8a/`
3. 把官方 demo 里的 Kotlin 封装（`OnlineRecognizer` / `OnlineStream` / `*Config`）
   拷进来，实现我们的 `AsrEngine` 接口
4. 中文模型建议用流式 zipformer（中英双语），例如
   `sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20`
5. 效果：**边说边出字**，延迟从 2~3 秒降到 1 秒级

> 另有一个第三方 Maven 包 `com.bihe0832.android:lib-sherpa-onnx`（我看到的最新 6.25.21），
> 但它不是官方发布，版本与 API 对应关系需要你自己验证——**我不建议拿它做主力**。

## 6. 常见错误对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 构建报 `NDK not configured` / 找不到 ndk 26.1.10909125 | NDK 没装或版本不符 | CI：看 workflow 的安装步骤；本地：SDK Manager 装同版本 |
| 构建报 FetchContent 下载失败 | 构建机访问不了 GitHub | 换有网的机器；或把 whisper.cpp 克隆到本地改成 `SOURCE_DIR` |
| 构建报 whisper.cpp 的 CMake 选项不认识 | 该 tag 的选项名变了 | 只是警告可忽略；失败就把 `GIT_TAG` 换一个版本 |
| 运行日志里仍是 `[ASR未接入]` | 模型没就绪或原生库没加载 | 先确认第 3 步下载完成、文件 >10 MB；再看 logcat 有没有 `UnsatisfiedLinkError` |
| 识别出乱码/繁体/英文 | 语言自动检测跑偏 | 把 `InterpreterService.ASR_LANGUAGE` 从 `"auto"` 改成 `"zh"` |
| 识别很慢（>5 秒） | 模型太大 / 线程太少 / 发热降频 | 换 tiny、把线程调到 4~6、缩短 Segmenter 的 `hangoverMs` |
| 字幕一直不更新 | 环境噪声导致 VAD 切不出句子 | 换 Silero VAD（见 `Segmenter.kt` 注释），或先降低 `silenceThreshold` |

## 7. 诚实声明

- 本版代码我**同样无法编译验证**（本机没有 JDK/NDK/SDK）。
- 风险最高的两处：**whisper.cpp 的 `GIT_TAG` 是否还存在**、
  **JNI 方法签名与 Kotlin `external fun` 是否完全对应**。
- 但架构上做了保护：即使原生库构建失败或模型缺失，App 也能正常启动并退回占位识别，
  不会让你连界面都进不去。
- 出问题就把 **Actions 的红色日志** 或 **logcat 的报错**发我，我照错改。

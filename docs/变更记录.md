# 变更记录

## v1.2-error（当前）—— 翻译报 400 时，把服务器的原话显示出来

**你的现场**：字幕第二行显示 `[HTTP 400] エコをかかっているのか…`（原文照抄，没有译文）。

**问题所在**：400 = **服务器拒绝了这个请求**（不是 Key 错，Key 错是 401）。
但我之前的代码只显示状态码，**把服务器给的原因丢掉了**，所以看不出到底哪一步不对。

**修复**：
1. **错误信息里带上服务器的原话**：从响应体里抓 `error.message`，例如
   `[HTTP 400 请求被拒] Model Not Exist` / `Invalid Format` / 余额不足 等，
   直接显示在字幕第二行，同时写进日志。
2. **不再发送 `temperature` 参数**：不同服务商对取值范围要求不同（有的不接受 0），
   用服务端默认值最保险——少一个被 400 拒绝的理由。
3. 启动时日志会打印**实际使用的接口地址与模型名**（不含 Key）：
   `翻译接口：https://api.deepseek.com/v1 ｜ 模型：deepseek-chat`
   对不上时一眼就能看出来。
4. 常见状态码加上中文解释：401 Key 无效 / 402 余额不足 / 404 地址不对（要含 /v1）/
   429 太频繁。

## v1.1-token —— 修 HTTP 401 与"安全键盘不许粘贴"

**你的现场**：检查更新报 `HTTP 401`；Token 根本粘不进输入框——系统的**安全键盘**禁止粘贴。

**根因**：密码类 `inputType` 会触发系统的安全键盘，HyperOS/MIUI/ColorOS 等 ROM 会禁掉长按粘贴。
Token 没进字段 → 接口收到空凭据 → GitHub 返回 401。

**修复**：
1. 翻译 API 的 Key 与更新 Token 两个字段都加 **「📋 粘贴」按钮**：
   直接读剪贴板写入，**完全绕开输入法**，安全键盘拦不住。
2. 两个字段的 `inputType` 从 `textVisiblePassword` 改为 `textNoSuggestions`
   （不再触发安全键盘；长按粘贴通常也能用了，粘贴按钮是双保险）。
3. 401 错误信息**分类说明**：Token 没填 / 只粘了一半（会报字符数）/ 权限不足或过期。
4. 检查更新时状态行显示 `Token 已填 93 字符（github_pat_…ABCD）`，
   一眼确认 Token 有没有真的进去（不会泄露完整值）。

## v1.0-perf —— 识别慢 10 倍的真凶 + 你提的三件事

### 0. ★ 关键修复：5 秒音频识别用了 56 秒

**证据（你截图里的日志）**：
```
#1 (5100ms 音频 · 识别 56491ms · 翻译 742ms · 待处理 3)
心跳：已出字幕 1 句 · 识别为空 0 次 · 丢弃 11 段 · 待处理 3 段
```

**根因（我的构建配置错了，不是手机不行）**：
AGP 给 debug variant 传的是 `-DCMAKE_BUILD_TYPE=Debug`，而 CMake 的 Debug 配置默认只有
`-g`（**零优化**）。于是 whisper.cpp / ggml 全被按 `-O0` 编译。ggml 的矩阵运算是纯计算循环，
`-O0` 下慢 **10~50 倍**——这正好解释 56 秒。

**修复**：
- `CMakeLists.txt` 里把 `CMAKE_C_FLAGS_DEBUG` / `CMAKE_CXX_FLAGS_DEBUG`
  强制为 `-O3 -DNDEBUG`（Release 也一并固定），无论 AGP 传什么配置都走优化版
- `app/build.gradle.kts` 再加一道 `-DCMAKE_BUILD_TYPE=Release` 作为双保险
- 线程默认从 3 调回 **4**（优化后 4 线程既不烫也够快）

**预期**：tiny 模型 5 秒音频从 56 秒降到 **0.3~1 秒**，base 降到 1~2 秒，
"丢弃 N 段"应归零，字幕会跟得上。

### 1. 为什么选不到 DeepSeek V4.1 / 4.0-pro
模型名迭代太快，**写在代码里的列表必然追不上**。新增
**「从服务器拉取模型列表」** 按钮：调 `GET {baseUrl}/models`（OpenAI 兼容接口都提供），
把**服务端当前支持的全部模型**灌进下拉框直接选，DeepSeek 出到几版都在里面。
文本框仍然保留，可以手打任何名字。

### 2. API Key 输入框不能粘贴
原因：`inputType="textPassword"` 会被很多 ROM（HyperOS / MIUI 等）**禁止长按粘贴**。
现在改为默认**明文输入**（粘贴正常），并新增「隐藏 API Key」勾选框——
需要遮屏时再勾（勾上后可能又无法粘贴，这是系统行为，不是 App 限制）。

### 3. 应用内更新（不再手动下载 APK）
- **CI 侧**：每次构建自动把 APK 发成一个 **GitHub Release**（tag = 版本号）
- **App 侧**：设置页新增「应用内更新」卡片 → 点 **检查更新并下载** →
  比对版本号 → 下载 APK（写进系统下载目录，用 MediaStore，**不需要任何存储权限**）
  → 调起系统安装器，你点一下「安装」
- **私有仓库**：填一个**只读 token** 即可（只存本机，不进代码）
- 首次使用系统会要求你允许「安装未知应用」，App 会自动带你到那个开关

## v0.6-norepeat —— 修「卡在同一句话上反复不动」

**你的现象**：日文识别出来、也翻译出来了（说明模型和 DeepSeek API 都通了），
然后字幕**锁死在同一句**，不再更新。

**根因（两个叠加）**：

1. **whisper 上下文污染（主因）**。`whisper_full_params.no_context` 默认是 `false`，
   也就是**把上一次的输出当作这次的上下文提示**。而我的"边说边出"是
   **每 1.2 秒把重叠的 5 秒音频重跑一遍**——同一段音频被反复喂进去，
   模型被自己的输出带偏，最终锁死在反复吐同一句上。
   这正是 whisper 圈里著名的 repetition loop。
2. **临时识别把最终识别挤死**。两者共用一个工作线程，临时识别耗时（base 跑 5 秒音频
   ≈1~3 秒）把线程占满，最终句子排在后面越堆越多，表现为"字幕不动"。

**修法**：

| 位置 | 修改 |
|---|---|
| `whisper_jni.cpp` | `no_context = true`（每次独立解码）、`suppress_blank = true`（配合前者的必要项）、`temperature_inc = 0.2`（遇重复可温度回退逃出） |
| `whisper_jni.cpp` + `WhisperAsrEngine` | 新增 `single_segment` 参数：**临时识别强制单段**，最终识别才允许多段 |
| `AsrEngine` | 新增 `transcribePartial()`，默认等同 `transcribe()`，让流式引擎走更保守的解码路径 |
| `StreamingTranscriber` | 结果与上次完全相同就不再刷屏（第二层兜底） |
| `InterpreterService` | **最终识别优先**：只有队列空了才做临时识别；队列上限 3，超了丢最旧的；字幕末行加 `#序号 / 识别耗时 / 翻译耗时 / 待处理数`，一眼看出是否在推进 |

**验证方法**：启动后看字幕最后一行的 `#1 #2 #3` 是否持续递增。
如果序号不动，把那一行截图给我——那就是另一个问题了。

## v0.5-model —— 修「模型下不下来 / 看不出模型没就绪」

**你遇到的现场**：悬浮字幕显示 `〔识别中〕[ASR未接入 5000ms]`，看起来"无法翻译"。

**真相**：识别模型没就绪 → 用的是占位识别 → 返回的是假字符串，
**根本没有真实文本可以翻译**。翻译那一环是被连带的，不是它坏了。

**这一版改了四处**：

1. **下载内置国内镜像**：每个模型两个源，官方源失败自动切 `hf-mirror.com`，
   日志会明确写出"尝试源 1/2""该源返回 HTTP xxx""下载内容过小，疑似被拦截"。
2. **新增「3b. 从文件导入模型」**：走系统文件选择器（SAF），选中的 `ggml-*.bin`
   直接复制进 App 私有目录——**完全不需要存储权限**，专治下载被墙。
3. **多目录查找**：除了 App 私有目录，还会找
   `/sdcard/Download/offlineinterp/`、`/sdcard/Documents/offlineinterp/`，
   你从电脑传进去的模型放这里也能被识别。
4. **不可能再误解**：
   - 主界面「当前配置」会写清 `识别=tiny ｜ 未就绪 —— 点第 3 步`，并列出**所有查找过的路径**；
   - 选识别引擎时会逐条打印候选路径；
   - 悬浮字幕在模型缺失时直接显示"⚠ 识别模型未就绪，现在显示的全是占位文字，不可能有翻译"；
   - 占位识别时**不再空跑临时字幕**（省电）。

**用法**：设置页选好模型（先选 tiny）→ 主界面第 3 步下载，或第 3b 步导入 →
看到"已就绪（xx MB）→ 路径"再点第 5 步。

## v0.3-stop —— 修复「无法停止屏幕共享」

**你报的 bug**：v0.1 / v0.2 只做了"开始捕获"，没有任何"停止"入口，
一旦点开就只能靠强杀 App 或重启手机才能结束屏幕共享。

**原因**：`MainActivity` 只发了启动指令，`InterpreterService` 也只处理启动；
`MediaProjection` 的生命周期没接停止路径，前台服务通知也没有操作按钮。

**修法**：新增统一的收尾逻辑 `teardown()`，并挂上三个停止入口，
任一个触发都会：停止音频采集 → 结束切句 → 中断识别线程 → 关掉悬浮窗 →
释放识别模型 → 结束 MediaProjection → 撤下前台通知。

| 停止方式 | 位置 | 适用场景 |
|---|---|---|
| ① App 内按钮 | 主界面第 6 步「停止捕获 / 结束同传」 | 手里正开着 App |
| ② 通知栏按钮 | 下拉通知栏 → 「离线同传」通知上的 **停止同传** | 正在看视频、不想切回 App |
| ③ 系统「停止共享」 | 顶部"屏幕共享中"提示里选停止 | 系统级兜底（回调 `onStop` 也会走同一套收尾） |

**另外的界面改进**：
- 按钮会按运行状态自动启用/禁用：捕获中时「探针」「启动」变灰，「停止」可点；反之亦然。
- 点通知正文会直接打开 App（界面里就有停止按钮）。
- 日志里明确写出三种停止方式，不用再猜。

> 注意：每次云端构建用的签名不同（debug key 每次都会重新生成），
> 所以**装新版本前请先卸载旧版本**，否则会提示"应用未安装"。
> 我在 workflow 里加了 debug keystore 缓存，从这个版本起签名会固定下来，
> 以后就能直接覆盖安装了。

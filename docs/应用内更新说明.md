# 应用内更新 —— 完整操作流程

> 目标：以后你不再需要手动去 GitHub 下载 APK，在 App 里点一下就能升级。

---

## 一、它到底是怎么跑的（原理，30 秒看懂）

```
我改代码 → 你 Push → GitHub Actions 自动构建
                          ↓
             自动把 APK 发成一个 Release（tag 就叫版本号，例如 v1.0-perf）
                          ↓
你手机上的 App：设置 → 「检查更新并下载」
                          ↓
           调 GitHub 接口读"最新 Release 是哪个版本" + "APK 下载地址"
                          ↓
           版本号不一样 → 下载 APK 到系统"下载"目录 → 调系统安装器
                          ↓
                    你点一下「安装」→ 升级完成
```

三个关键点：
- **版本号来源**：CI 从 `app/build.gradle.kts` 的 `versionName` 里读，所以**每发一版我都会 +1**。
- **下载不需要存储权限**：用系统的 MediaStore 写进"下载"目录（Android 10+ 无需任何权限）。
- **签名必须一致**：CI 缓存了 debug 签名，所以能直接覆盖升级；如果哪天缓存被清掉，
  安装会报"应用未安装"，那就先卸载旧版再装（会丢模型，需要重新下载）。

## 二、一次性准备（只需要做一次）

### 第 1 步：手动装一次 v1.0
因为 **v0.9 里还没有更新功能**，这次必须照老办法：Actions → 下载 artifact → 覆盖安装。
（从 v1.0 往后，就能用下面的流程了。）

### 第 2 步：允许本应用"安装未知应用"
第一次点更新时，系统会拦一下。两种方式：

- **自动**：App 会直接跳到「安装未知应用」页面，你把「离线同传」的开关打开即可。
- **手动**：手机设置 → 应用 → 特殊应用权限（或"安装未知应用"）→ 找到「离线同传」→ 允许。

### 第 3 步：准备一个只读 Token（因为仓库是私有的）
私有仓库的 Release 接口需要授权才能读。做法：

1. 电脑浏览器打开 GitHub → 右上头像 → **Settings**
2. 左侧拉到最底 → **Developer settings**
3. → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
4. 填写：
   - **Token name**：随便，例如 `offline-interp-update`
   - **Expiration**：建议 90 天或 1 年（到期后重新生成一个填进去）
   - **Repository access**：选 **Only select repositories** → 勾 **linghot/void**
   - **Permissions** → 展开 **Repository permissions** → 找到 **Contents** → 选 **Read-only**
     （只读就够，别给写权限）
5. 点 **Generate token** → 复制那串 `github_pat_...`（**只显示一次**）

> 如果你不想用私有仓库，也可以把仓库改成 **Public**：那样这一栏留空就行，
> 别人能看到代码（但看不到你的 API Key，因为 Key 只存在你手机里）。

## 三、每次升级怎么做（4 步）

1. 我推完新代码、Actions 跑成绿勾（并自动发了 Release）
2. 手机打开 App → **⚙ 设置** → 拉到最下面 **「应用内更新」** 卡片
3. 确认两栏：
   - **更新源**：默认已填 `https://api.github.com/repos/linghot/void/releases/latest`（不用改）
   - **只读 Token**：粘贴第 3 步拿到的 `github_pat_...`（只需填一次，会记住）
4. 点 **「检查更新并下载」**，然后看下面那行状态文字

### 你会看到的几种结果

| 状态行显示 | 含义 | 你该做什么 |
|---|---|---|
| `当前版本：1.0-perf，正在检查…` | 正在调接口 | 等 2~5 秒 |
| `已是最新版本（v1.0-perf）` | 版本号一样 | 说明还没出新版，或我没升版本号 |
| `发现新版本 v1.1-xxx，开始下载…` → `下载中 47%（23 MB）` | 正在下载 | 等它下完（约 30~80 MB） |
| `已下载 62 MB，请在系统弹窗里点「安装」` | 下载完成，已调起安装器 | **在系统弹窗里点「安装」** |
| `检查失败：还没发布过 Release…` | CI 还没跑过带 Release 的构建 | 确认 Actions 是绿勾 |
| `检查失败：HTTP 401/403：私有仓库需要…` | Token 没填 / 填错 / 权限不够 | 重做第 3 步（Contents 只读） |
| `检查失败：HTTP 404` | 更新源地址写错，或仓库改名 | 检查地址栏 |
| `更新失败：下载失败 HTTP 403` | Token 权限不足 | 确认是 Contents: Read-only |
| `更新失败：下载异常 InterruptedException` | 下载被中断（切网/息屏） | 重试，保持网络稳定 |

### 装完之后
- APK 也会留在手机 **「下载」目录**里（文件名 `offline-interp-v1.1-xxx.apk`），
  想手动重装、或传到别的手机都行。
- 升级**不会**丢设置和模型（同签名覆盖安装）。

## 四、专治两种"填不进去"的情况（v1.1 起）

### 1. 系统弹的是「安全键盘」，长按没有粘贴
密码类输入框会触发系统的安全键盘，**很多 ROM（HyperOS / MIUI / ColorOS）会禁止粘贴**。
所以 v1.1 给两个字段各加了一个按钮：

**「📋 粘贴 API Key」** 和 **「📋 粘贴 Token」**

它**直接读剪贴板写入**，完全不经过输入法——安全键盘拦不住它。

用法：先在浏览器/备忘录里选中 Token → 复制 → 回 App → 点那个粘贴按钮。
按钮下方会提示"已粘贴（xx 个字符）"，用它核对有没有粘全。

### 2. 报 HTTP 401
401 = **服务器认为你没带有效凭据**。v1.1 会明确告诉你是哪种：

| 状态行 | 原因 | 处理 |
|---|---|---|
| `HTTP 401：Token 没填…` | 字段是空的（多数是粘贴失败） | 用「粘贴 Token」按钮 |
| `HTTP 401：Token 只有 12 个字符…` | 只粘了一半 | 重新复制完整 Token（`github_pat_` 约 93 字符） |
| `HTTP 401：Token 无效或权限不足…` | 权限没给 Contents: Read-only，或 Token 过期/被撤 | 回 GitHub 检查或重新生成 |

> 顺带一提：检查更新时状态行会写 `Token 已填 93 字符（github_pat_…ABCD）`，
> 这样你不用猜，一眼就知道 Token 到底有没有进去。

## 五、出问题时的备用方案（永远可用）

不想折腾 Token，或更新链路坏了，就走老路：

1. 电脑打开 `https://github.com/linghot/void/releases` → 下载最新那个 `.apk`
   （或 Actions → 该次运行 → 底部 Artifacts）
2. 传到手机 → 点击安装 → 覆盖

- CI 里保持 `action-gh-release` 那一步正常（它负责把 APK 挂到 Release 上）
- 如果哪天你换了仓库名，告诉我，我把默认更新源地址一起改掉
